# PF400 firmware command SDK implementation plan

**Goal:** Implement the 82 non-vision commands in customer-delivery Tcp_cmd_server_ablelabs as an independent Python package.

**Architecture:** A blocking, standard-library TCP transport with independent motion/status connections and per-channel serialization. Explicit generated command methods share validation/serialization and return an immutable response. An asynchronous adapter offloads blocking calls for asynchronous Python consumers. No application sequence, site configuration, controller program or firmware is copied into the SDK.

**Tech stack:** Python >=3.10, socket/threading/asyncio, setuptools; pytest for development only.

1. Write behavioral tests for firmware coverage, wire arguments, response parsing, errors, fragmentation, deadline/EOF recovery, independent channels, mode transitions, Exit, input injection and asynchronous calls. Run and record the expected missing-package failures.
2. Extract source provenance and documentation for the command manifest. Exclude Vprocess, VresultLoc, VresultInfo, VresultInspect, VToolProperty, VresultInfoString, StereoParam and StereoLocate.
3. Implement transport and protocol. Bound socket operations and lock acquisition by one deadline; never retry sent commands; close a desynchronized channel on network/protocol failure. Preserve negative data values and unknown device errors.
4. Generate inspectable synchronous/asynchronous APIs and per-command reference from reviewed metadata. Test special firmware behavior: quoted Pc strings, deferred extra axes, HomeAll scope, reset restrictions and active gripper argument groups.
5. Add installation and read-only Python examples, firmware compatibility/verification limits, CI, and source notices. Build wheel/sdist and install the wheel in an isolated environment; verify no firmware or vision implementation is packaged.
6. Initialize the requested local repository and copy only SDK artifacts to it. Remote creation/publication and an open-source license require their final repository owner/license to be specified; local development proceeds independently.

Physical robot calls, power/home/motion and firmware upload are outside this implementation verification.
