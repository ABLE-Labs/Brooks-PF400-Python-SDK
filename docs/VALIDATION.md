## 기능별 예제 검증

- 번호별 동기 예제는 작업별 실행 파일로 분리했으며, 비동기 조회 예제도 유지합니다. 파일 상단 변수로 설정하고 main()을 직접 실행합니다.
- 파일 import만 할 때는 연결하지 않는지 확인했습니다.
- 필수 작업·목표 값이 없으면 연결 전에 ValueError로 종료하는지 검사했습니다.
- 설정한 main()을 직접 실행해 전송 명령과 순서를 루프백 TCP 서버에서 확인했습니다.
- 오류 코드 출력과 자동 재시도 없음도 확인했습니다.
- 각 파일은 공통 CLI 도구 없이 독립적으로 실행할 수 있습니다.
- 예제 안내서는 sdist에 포함하며 FastAPI 예제는 포함하지 않습니다.

## JSON 티칭 검증

- 현재 관절 좌표 저장 후 같은 이름을 불러와 이동하는 흐름을 루프백 서버로 확인했습니다.
- 이름별 갱신, 다른 위치·메타데이터 보존, 신규 파일 생성과 임시 파일 정리를 확인했습니다.
- 잘못된 JSON·문자열·bool·NaN/Infinity 좌표를 거부하고 원본 파일을 보존합니다.
- 위치 누락 시 연결하지 않으며, 장비와 저장값의 축 개수가 다르면 이동 명령을 보내지 않습니다.
- 배포 JSON은 실제 장비 티칭 전이므로 빈 위치 목록으로 제공합니다.

## 축 수동 모드 예제 검증

- 선택 축 모드는 WhereJ로 축 개수 확인 후 Attach 1 → FreeMode -1 → 선택한 각 축의 FreeMode 순서로 전송함을 확인했습니다.
- restore는 AXES와 관계없이 FreeMode -1만 전송합니다.
- 빈 목록·중복·잘못된 축 번호/타입·작업은 연결 전에 거부합니다. 실제 축 개수 범위를 벗어나면 WhereJ 조회 후 모드 변경 전에 종료합니다.
- 전원·원점·브레이크·이동 명령을 자동 전송하지 않습니다.
- 검증은 루프백 TCP 서버 기준이며 실제 축 해제·복원 동작은 미검증입니다.
