# 검증 기록

`0.1.0a1` 기준입니다. 모든 검증은 소프트웨어 검증이며, 실장비 검증은 아직 하지 않았습니다.

## 기준과 범위

- 펌웨어: PF400 TCP Command Server (TCS)
- 소스 버전 문자열: `Command Server 3.0D4 10-25-2024`
- 공개 Cmd_* 선언 90개 중 비전 명령 8개 제외, SDK 메서드 82개
- 원본 파일별 SHA-256·명령 선언 위치: [firmware_manifest.json](firmware_manifest.json)
- 확인 환경: Windows / CPython 3.10.11
- 모든 TCP 연결은 127.0.0.1의 테스트 서버 대상입니다.

## 예제 확인 내용

모든 예제는 루프백 TCP 테스트 서버로 전송 명령과 순서를 확인했습니다.

- **공통:** import만으로 연결하지 않습니다. 필수 목표값이 없으면 연결 전에 `ValueError`로 종료합니다.
  30개 실행 파일을 다른 작업 디렉터리의 별도 Python 프로세스에서 불러올 수 있습니다. 자동 재시도는 없습니다.
- **02 시작·종료:** 원점 완료/미완료, 전원 오류 시 중단, Home 미완료 시 그리퍼 개폐 금지, 종료 명령 순서.
- **03 프로파일:** JSON 왕복 저장, 잘못된 필드·NaN·손상 파일 거부, 저장 교체 실패 시 원본 보존.
  시작·제어 준비가 같은 JSON을 연결 전에 검증하고 적용합니다.
- **04~06·13 이동:** 그리퍼 자동 열기 없음. 원점 미완료나 축 개수 불일치 시 이동 명령을 보내지 않습니다.
- **07·08 그리퍼:** 조회·설정은 전원 ON 없음, 잡기 실패 시 중단, 해제 후 완료 대기.
- **09 컨트롤러 티칭:** GPO 불러오기 후 지정 슬롯 이동, `LOCATION_INDEX` 미입력 시 연결 전 종료.
- **13 PC 티칭:** 이름별 갱신, 다른 위치·메타데이터 보존, 신규 파일 생성과 임시 파일 정리.
  잘못된 JSON·문자열·bool·NaN/Infinity 좌표를 거부하고 원본 파일을 보존합니다.
  `POSITION_NAME` 미입력이나 저장되지 않은 이름이면 연결하지 않습니다. 배포 JSON에는 저장된 위치가 없습니다.
- **14 수동 모드:** 축 개수 확인과 공통 초기화 후 선택한 축만 FreeMode를 보냅니다. restore는 `FreeMode -1`만 보냅니다.
  빈 목록·중복·잘못된 축 번호는 연결 전에 거부합니다.

## 실장비 검증 상태

PF400 접속·동작, 전원·원점, 정지 성능, 그리퍼·높이 감지, 레일·팔레트·제조사 작업 루틴은 아직 검증하지 않았습니다.
01·02 예제는 이전 버전을 실장비에서 실행해 본 기록이 있지만, 현재 버전으로는 다시 확인하지 않았습니다.

실장비에서 확인할 사항:

- 실제 탑재 펌웨어와 manifest 기준 소스 일치 여부 및 Version 응답
- 각 명령의 인자 단위, 적용 축·그리퍼·옵션, 경계값과 반환 필드
- 동작 명령의 응답 시점과 완료 대기, 시간 초과 후 상태 확인 절차
- 이동 중 status 채널 대상 선택과 Halt, Reset 후 세션 상태
- 브레이크·수동 모드, 원점·전원, 충돌 확인이 없는 제조사 루틴의 실제 동작
- 동시 클라이언트와 전역 Mode 변경 운영 조건
